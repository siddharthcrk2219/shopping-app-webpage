PROJECT OVERVIEW
Thread & Form is a Flask application for a clothing catalog and review system. The users can browse clothes, filter by department/class, search, see details of an item and its reviews, and add new reviews. One of the models that was developed during the Milestone I experiments makes a prediction on binary recommendation using the review.

SYSTEM REQUIREMENTS AND EXECUTION
Python version: 3.12
Dependencies: listed in requirements.txt.

Extract the submission and open a terminal in the folder containing app.py.
On Windows PowerShell, run:

    py -3.12 -m venv .venv
    .\.venv\Scripts\python.exe -m pip install -r requirements.txt
    .\.venv\Scripts\python.exe app.py

Open http://127.0.0.1:5000 in a web browser. The terminal must remain running
while using the website. Press Ctrl+C to stop the server.

The fitted model is bundled; retraining and external embedding downloads are
not required to run the application. Internet access is needed to install
Python dependencies. Bundled local image assets work without internet access.

MAIN FUNCTIONALITIES
1. Homepage: paginated previews of unique clothing items from the course CSV.
2. Categories: department and class filters reflecting the dataset hierarchy.
3. Item details: title, description, category, original rating summary and reviews.
4. Search: matching item count and previews, with singular/plural normalization
   such as dress/dresses. All normalized query terms must match item metadata.
5. Review creation: review title, description and a user-selected 1-5 star rating.
6. Prediction: a visible binary recommendation generated from the review text.
7. Override: the reviewer can choose a different final recommendation.
8. Persistence: confirmed reviews are stored in SQLite and accessible through
   their own URLs and the corresponding clothing item's page.

DESIGN
The catalog lists items by their department and class; every Clothing ID has its own details page.
This takes into account the relationships in the provided dataset and doesn’t include every single review as a new item.
The first line in the CSV for an ID contains all canonical information about the product.

The interface is capable of supporting responsive layouts, labeled forms,
keyboard focus and reduced motion preferences. The CSS files and images are stored
in static/ and layout templates are stored in templates/. The display images are
illustrative and not necessarily representative of the clothing products in the dataset.

MILESTONE I MODEL INTEGRATION
Selected experiment: Bag-of-Words with Multinomial Naive Bayes, evaluated in
s4175880_task2_3.ipynb / s4175880_task2_3.py.

The original Milestone I archive contained code and feature artifacts but no
serialized fitted classifier. The selected experiment was refitted and exported
using the saved vocabulary, word-count representation and original settings:

    Reviews:             19,662
    Vocabulary features: 7,529
    Train/test split:    Stratified 80/20, random_state=42
    Classifier:          MultinomialNB with default parameters
    Representation:      Sparse word counts using the saved vocabulary indices

The preprocessing includes lowercase conversion and tokenization using the Milestone I regular expression tokenizer.
Tokens from vocabulary terms only will contribute to the feature vector. The model,
which consists of both vectorizer and classifier, is saved together in models/recommender.pkl.

The 19,662 reconstructed count vectors coincide with the count_vectors.txt file.
Re-evaluation on refitted model gives the same values as in the notebook:

    Accuracy:  0.868040
    Precision: 0.925844
    Recall:    0.911746
    F1 score:  0.918741
    ROC AUC:   0.905000

This version of processed.csv strips out 40 more words that still appear in the saved
vocabulary/count vectors. The pair of vocabulary/count vectors is chosen to be the gold
standard as it is an exact duplication of the performed experiments. As the original vocabulary
was generated before the split, these metrics duplicate Milestone I rather than provide a new,
clean test for the model. See more in the DOCUMENTATION file. FastText and GloVe are not needed.

REVIEW WORKFLOW AND STORAGE
The model receives the review description and predicts:
    0 = Not recommended
    1 = Recommended

Star Rating is chosen by the user himself/herself, not generated by the model. On the confirmation page,
the model-generated rating appears, and the reviewer can choose his/her own rating for the article.
Both the ratings are saved along with the Title, Description, Star Rating, and the Clothing ID.

Published reviews are stored in the data folder under reviews.sqlite3 file, created automatically at the first run.
Reviews stay saved even after the re-running of the application. Review URL will be like: 
http://127.0.0.1:5000/reviews/<id>. Drafts are stored in data/drafts/ folder. 
There is no need for customer login or checkout.

TESTING
Run the integration tests from the project directory:

    .\.venv\Scripts\python.exe -m unittest -v

Test cases include browsing paths, image paths, singular and plural search,
empty search results, recommendations creation, manual intervention, reviews fetching
after application restart, input validation and HTML encoding.
All test cases use a temporary database and do not affect the reviews from
the application. The created baseline successfully passed all those test cases.
Later styling and image modifications are out of scope of the baseline test
validation.
